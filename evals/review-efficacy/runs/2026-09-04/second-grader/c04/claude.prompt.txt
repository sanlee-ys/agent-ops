=== BEGIN REVIEW ===
**Summary:** The dest-flag `=`-parsing fix is correct, but the mirrored src-flag fix has an inverted bug, and no test covers that path.

- **auto-fix:** In `_copy_operands` (line 1561), the new `_SRC_FLAGS` branch does `positional.append(tok.split("=", 1)[0])` — this appends the flag name (the text before `=`), not the attached value. It should mirror the `_DEST_FLAGS` branch and use `tok.split("=", 1)[1]`. As written, a credential source passed via an `=`-attached src flag (e.g. `cp --src=~/.env dst`) is recorded as the literal flag text instead of the path, so the guard cannot match it against credential patterns — this is the exact bug the PR claims to fix, reintroduced on the source side instead of the destination side.
- **auto-fix:** No test exercises the new `_SRC_FLAGS` `=`-attached branch. Both new blocked-case tests (`cp --target-directory=/tmp ~/.env`, `mv --target-directory=/tmp ~/.ssh/id_ed25519`) and the new allowed-case test (`cp --target-directory=/tmp README.md`) only exhaust the `_DEST_FLAGS` code path. A test using an `=`-attached src flag (e.g. whatever member of `_SRC_FLAGS` supports `--flag=value` syntax) with a credential source is needed to prove the src branch works — and would have caught the bug above.
- **ask-user:** The PR title and changelog comment (lines 81-84) describe only the dest-flag `=`-parsing fix, but the diff also changes `_SRC_FLAGS` handling. Confirm this additional, currently-broken change was intentional scope for this PR rather than an unreviewed addition.

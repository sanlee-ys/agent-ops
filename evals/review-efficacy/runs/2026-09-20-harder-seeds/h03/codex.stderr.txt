## Redlines

These rules bind every vendor, wired or not. A vendor with no guard wired
for a rule still owes one; the gap is a thing to close, not a reason to
route the work elsewhere.

- Never expose a credential, a secret, or a secret store's contents.
- Never rewrite or force-push published history.
- Never perform a consequential mutation — a merge, a delete, a force-push,
  a message sent on the user's behalf — without the guard chain in place or
  an explicit human step.
- Never use a permission-bypass flag as a substitute for guard wiring. A
  bypass flag removes the permission layer a guard may depend on; it does
  not remove the guard's own obligation.

Enforce each rule mechanically, per vendor. A rule enforced for one vendor
only is a gap, not a default.

## Command shapes

These shapes apply in every harness with a permission-gated or
approval-gated command runner:

- Run each read-only inspection command on its own. Do not chain commands
  with `&&`, `;`, or `|` for inspection — chain only when a later command
  genuinely depends on an earlier one's result.
- Scope a git command to its repository explicitly (for example
  `git -C <path> <verb>`). Do not `cd` into a repository first and run a
  bare command.
- Treat a destructive-looking git verb — a hard reset, a history rewrite, a
  forced branch delete, a force-push — as a step that needs an explicit
  human decision, not a default path.
- Avoid an improvised or unfamiliar command shape where a known, working
  shape exists. A novel shape is the most common source of an avoidable
  approval prompt or a silent failure.
- A command form that works in one shell does not always work in another.
  Confirm a new shape once before repeating it across many calls.

Two independent defects produced that contradiction.

## 1. The metadata exemption was positional

v2 classified a segment by its **leading** command. Bare `Test-Path <path>`
reached the safe allowlist; wrapped in a substitution, the leading token is a
quoted string, which is not a safe command, so the segment fell to
default-deny. A probe confirmed the split before any code changed — the bare
form already passed, so the exemption existed and was simply unreachable here.
The same shape blocked `if (Test-Path ~/.ssh/id_rsa)`.

v2.3 classifies each **nested command unit** on its own terms (`$( )`,
backticks, `<( )`, bare `( )` groups) and then judges the outer command with
those units blanked. The mere presence of `$(` is no longer disqualifying; the
substitution gets read instead.

Two properties keep the recursion from becoming a laundering hole:

| Shape | Why it still blocks |
| --- | --- |
| `cat $(echo ~/.ssh/id_rsa)` | Clearing a unit must not hide the path from a reader that **receives** it. Only a unit whose output is a bare value (`Test-Path`, `test`) stops the outer command being scrutinised; `echo`/`ls`/a bare quoted path hand the path text onward. |
| `"$(Test-Path ~/.ssh/id_rsa; cat ~/.ssh/id_rsa)"` | A unit body is a command **list** and is re-split before classifying. |

The second was **found by an adversarial pass on this fix before it shipped** —
the first draft judged that body on `Test-Path` alone and let the chained
reader ride in behind it. The top-level splitter can't catch it: it leaves
separators inside quotes alone, which is exactly where the shape lives.

A paren inside a *quoted* string stays literal text and is not treated as a
unit, so an interpreter one-liner is not torn into fragments that each look
harmless.

## 2. `.pub` matched the private-key pattern

A `.pub` file is the *public* half of a keypair — printed, pasted into GitHub,
appended to `authorized_keys` as a matter of routine. Blocking it is a pure
false positive, and the kind that teaches reaching for `MASK-OK` on a
non-secret. Unlike `.pem` (ambiguous between a cert and a key, hence the
`key`/`priv` guard on `PUBLIC_CERT`), `.pub` is unambiguous by convention, so
`deploy-key.pub` is exempt too.

The pattern now matches the whole trailing suffix so the exemption still judges
a **complete** basename: `id_rsa.pub.bak` does not qualify. That is the
anchoring discipline `PUBLIC_CERT` learned in red-team round 2 — the first
draft got this wrong and two of my own tests caught it.

Three regressions in the tightened `Env:` rules. Each unblocks a form the old broad rule caught. I reviewed the diff text only and did not run the regexes.

- auto-fix: `_PS_ENV_DRIVE` starts with `(?:^|[\s;(])`, which replaces the old `\b`. An `Env:` dump that follows a quote or brace no longer matches. Examples are `powershell -Command "gci env:"`, `pwsh -c 'Get-ChildItem Env:'` and `{gci env:}`. The old `\b(dir|ls|gci)\s+env:` and `\bGet-ChildItem\b…` rules blocked these. Use a lookbehind such as `(?<![\w$.-])` instead of the fixed character set. Add tests for the quoted and brace-wrapped forms.
- auto-fix: `CRED_VAR_READ` has no optional quote before `Env:`. `Get-ChildItem "Env:GITHUB_TOKEN"` and `gci 'Env:GH_TOKEN'` were blocked by the old `[^|]*\bEnv:` rule. Now the dump rule misses them because `Env:GITHUB_TOKEN` is not the bare root. `CRED_VAR_READ` misses them because it requires `Env:` right after the whitespace or flags. The PR says the credential reads stay blocked, but the quoted form is a hole. Add `['\"]?` before `Env:` in the new alternative and pin it with a test.
- auto-fix: A partial wildcard on the drive is now allowed. `Get-ChildItem Env:GH*`, `Env:AWS*` and `Env:G*` print the values of every matching variable. The dump rule needs the token to end after the optional `*`, so these fail its lookahead. `_CRED_VAR` is not in the diff, so I cannot tell whether it catches the wildcard. The old rule blocked all of them. Treat any `*` or `?` inside the `Env:` token as a dump, and add a test.

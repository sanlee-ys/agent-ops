## Division of labor

Four vendors share this fleet. Each vendor owns a role:

- **Claude** is the control plane, the default implementer, and the final
  integrator.
- **Codex** challenges a design, reviews a consequential diff read-only, and
  diagnoses a stuck session. "Stuck" has a threshold: two failed
  hypothesis-driven attempts, or visible looping. First friction is not an
  escalation.
- **Cursor** executes bounded, IDE-native work: edit-test loops and UI
  verification on files no other vendor is touching at the same time.
- **Antigravity** is a measured Gemini-family lane: research, broad audits,
  browser and Google-stack work, capacity overflow, and a third opinion when
  Claude and Codex disagree.

Mechanical, green-CI work merges with no second-model pass. A second opinion
earns its cost on design-mode work, not on a rename.

**A harness, not a model family, decides the tool surface.** Running one
model family inside a different vendor's harness changes the tools
available. It does not supply model-family independence. Treat an
independent review as independent only when a different model family
produced it.

## Redlines

These rules bind every vendor, wired or not. A vendor with no guard wired
for a rule still owes one; the gap is a thing to close, not a reason to
route the work elsewhere.

- Never expose a credential, a secret, or a secret store's contents.
- Never rewrite or force-push published history.
- Never perform a consequential mutation — a merge, a delete, a force-push,
  a message sent on the user's behalf — without the guard chain in place or
  an explicit human step.
- Never use a permission-bypass flag as a substitute for guard wiring. A
  bypass flag removes the permission layer a guard may depend on; it does
  not remove the guard's own obligation.

Enforce each rule mechanically, per vendor. A rule enforced for one vendor
only is a gap, not a default.

### Review finding disposition

Every review finding carries exactly one label, assigned by the reviewer,
not by the session applying the fix:

- **`auto-fix`** — the fix is safe, mechanical, and does not change what the
  code is meant to do. The applying session fixes it without asking.
- **`ask-user`** — the fix touches intent: behavior, a contract, an
  interface, or a tradeoff the reviewer had to guess about. It is
  escalated, with the question stated.

An unlabelled finding defaults to `ask-user`. Full rule:
`delegation-policy.md` in this repo's root.

## Command shapes

These shapes apply in every harness with a permission-gated or
approval-gated command runner:

- Run each read-only inspection command on its own. Do not chain commands
  with `&&`, `;`, or `|` for inspection — chain only when a later command
  genuinely depends on an earlier one's result.
- Scope a git command to its repository explicitly (for example
  `git -C <path> <verb>`). Do not `cd` into a repository first and run a
  bare command.
- Treat a destructive-looking git verb — a hard reset, a history rewrite, a
  forced branch delete, a force-push — as a step that needs an explicit
  human decision, not a default path.
- Avoid an improvised or unfamiliar command shape where a known, working
  shape exists. A novel shape is the most common source of an avoidable
  approval prompt or a silent failure.
- A command form that works in one shell does not always work in another.
  Confirm a new shape once before repeating it across many calls.

## What happened

On 2026-07-26 two sessions worked one direct-to-main repo in the same clone. Session B reset past a commit Session A had already pushed, recommitted its own work, and force-pushed over the top. Session A's commit was recovered only because it was still in the reflog. Nothing announced the loss — it surfaced when a later edit could not find its own text.

## What the permission layer actually did

Checked before designing anything, because if the `ask` rules simply failed, the fix would be to repair them and stop. They did not simply fail:

1. **The reset was correctly allowed.** `git -C <repo> reset --soft de133f2` returned in 2.2s — no human read a prompt. Nor should one have: a soft reset destroys nothing locally, the operative gate is the auto-mode classifier (which denies resets under `[Irreversible Local Destruction]`), and the session had tagged a backup first.
2. **The force-push was not covered.** The `ask` list carried `--force` and `-f` in four shapes each, and **no** entry for `--force-with-lease`, so it fell through to the `git push` allow rule. A real gap — closed in the companion [REDACTED: publication boundary] PR.
3. **The lease protected nothing.** It compares the remote-*tracking* ref, and a background fetch had refreshed it, so the lease passed.

**The finding that drove the design:** closing gap 2 alone would not have prevented this, because finding 1 stands. The reset was the *safe* verb. The dangerous fact — *the range you are discarding holds a commit you did not write, and it is already on the remote* — is in the repository, not the command string, so no prefix rule and no classifier reading the command can reach it.

## The guard

`hooks/published-history-guard.py` — a stateful `PreToolUse` hook that asks git, at the moment of the call, what the command would actually destroy. Blocks a history-rewriting push or a backward `reset` on `main` **only when** published commits sit in the discarded range.

- **Both shapes, and the reset is the real fix** — it would have fired 49 seconds before the destructive push, before the session built two more commits on a doomed base.
- **`ls-remote`, never the tracking ref** — the tracking ref is what defeated `--force-with-lease`.
- **`main` only** — guarding feature branches would fire constantly for no risk, and a guard that cries wolf gets routed around.
- **Fails open, with one stated exception**: having identified a rewrite of `main`, it blocks if it *cannot verify* what would be destroyed.
- Override `REWRITE-MAIN-OK`, per-command, for deliberate rewrites like the de-identification squash.

## Options weighed (ADR-007)

- **(a) `pre-push` git hook** — fires three minutes too late, no propagation path for `pre-push` across the fleet. Worth revisiting as defence-in-depth.
- **(b) Server-side branch protection — DISQUALIFIED, not rejected.** Rulesets and branch protection are **paid features for private repos**; the API returns `403 Upgrade to GitHub Pro`. Available on exactly the repos that already have a PR gate, unavailable on the private direct-to-main ones that need it. Also a poor fit for legitimate rewrites, which would require toggling protection off and back on.
- **(c) A written rule alone** — necessary but insufficient; `git-staging-guard.py` exists because a behavioural rule failed twice in two days.

   331 +        return None
   332 +    if not targets:
   333 +        return None  # bare `git reset` unstages; it does not move the branch
   334 +
   335 +    branch = _current_branch(repo)
   336 +    if branch != PROTECTED_BRANCH:
   337 +        return None
   338 +
   339 +    target = targets[0]
   340 +    head = git(repo, "rev-parse", "HEAD")
   341 +    if head is None or git(repo, "rev-parse", "--verify", f"{target}^{{commit}}") is None:
   342 +        return None  # cannot resolve; not this hook's business to guess
   343 +
   344 +    out = git(repo, "rev-list", f"{target}..HEAD")
   345 +    if not out:
   346 +        return None  # nothing leaves the branch
   347 +
   348 +    dropping = out.splitlines()
   349 +
   350 +    remote_sha = _remote_head(repo, "origin", branch)
   351 +    if remote_sha is None:
   352 +        return Verdict(
   353 +            _CANNOT_VERIFY.format(
   354 +                action=f"reset of {branch} back to {target}",
   355 +                reason="`git ls-remote origin` did not answer",
   356 +                override=OVERRIDE,
   357 +            )
   358 +        )
   359 +    if remote_sha == "":
   360 +        return None
   361 +
   362 +    if not _ensure_local(repo, "origin", branch, remote_sha):
   363 +        return Verdict(
   364 +            _CANNOT_VERIFY.format(
   365 +                action=f"reset of {branch} back to {target}",
   366 +                reason=f"the remote tip {remote_sha[:9]} could not be fetched for inspection",
   367 +                override=OVERRIDE,
   368 +            )
   369 +        )
   370 +
   371 +    published = [c for c in dropping if _is_ancestor(repo, c, remote_sha) is True]
   372 +    if not published:
   373 +        return None  # your own unpushed work; the reflog has you covered
   374 +
   375 +    listing = _describe(repo, f"{target}..HEAD")
   376 +    ahead = git(repo, "rev-list", "--count", f"HEAD..{remote_sha}") or "?"
   377 +    return Verdict(
   378 +        _RESET_BLOCK.format(
   379 +            branch=branch,
   380 +            target=target,
   381 +            count=len(published),
   382 +            plural="" if len(published) == 1 else "s",
   383 +            listing="\n".join(f"    {line}" for line in listing) or "    (unreadable)",
   384 +            ahead=ahead,
   385 +            remote=remote_sha[:9],
   386 +            override=OVERRIDE,
   387 +        )
   388 +    )
   389 +
   390 +
   391 +_PUSH_BLOCK = """PUBLISHED-HISTORY GUARD: this force-push would delete {count} commit{plural} from {remote}/{branch}.
   392 +
   393 +Already on the remote, and gone if this proceeds:
   394 +{listing}
   395 +
   396 +Another session may have written these, and may already have pulled them. On
   397 +2026-07-26 this exact shape erased a sibling session's commit in `career`; it was
   398 +recovered from the reflog by luck, not by design.
   399 +
   400 +If your branch has diverged, rebase onto the remote instead of overwriting it:
   401 +    git -C <repo> pull --rebase        # replay your work on top of theirs
   402 +    git -C <repo> log --oneline -5     # confirm both sides survived
   403 +    git -C <repo> push                 # a plain push now suffices
   404 +
   405 +If dropping those published commits really is the intent - a deliberate history
   406 +rewrite, like the de-identification squash - prefix the command with {override}.
   407 +"""
   408 +
   409 +_RESET_BLOCK = """PUBLISHED-HISTORY GUARD: this reset would drop {count} published commit{plural} from {branch}.
   410 +
   411 +`git reset ... {target}` discards these, and the remote already has them:
   412 +{listing}
   413 +
   414 +origin/{branch} is at {remote} and is {ahead} commit(s) ahead of you, so this
   415 +branch has diverged - another session pushed while you were working. Resetting
   416 +does not resolve that; it just builds your next commits on a base the remote has
   417 +moved past, and the force-push that follows is what destroys their work.
   418 +
   419 +Rebase onto what the remote has instead:
   420 +    git -C <repo> pull --rebase        # replay your work on top of theirs
   421 +    git -C <repo> log --oneline -5     # confirm both sides survived
   422 +
   423 +If you are deliberately rewriting published history, prefix with {override}.
   424 +"""
   425 +
   426 +_CANNOT_VERIFY = """PUBLISHED-HISTORY GUARD: cannot verify what this {action} would destroy.
   427 +
   428 +{reason}, so the guard cannot tell whether commits from another session are
   429 +about to be dropped from `main`.
   430 +
   431 +This is the one case where the guard fails closed rather than open: the whole
   432 +point of it is that this operation is unrecoverable once it lands, and "the
   433 +network was down" is not a reason to find out afterwards.
   434 +
   435 +Check the remote by hand, or - if you are confident - prefix with {override}.
   436 +"""

   439 +def main() -> None:
   440 +    try:
   441 +        data = json.load(sys.stdin)
   442 +    except (json.JSONDecodeError, ValueError):
   443 +        sys.exit(0)
   444 +
   445 +    if data.get("tool_name") not in {"Bash", "PowerShell"}:
   446 +        sys.exit(0)
   447 +
   448 +    command = data.get("tool_input", {}).get("command", "")
   449 +    if not isinstance(command, str) or not command.strip():
   450 +        sys.exit(0)
   451 +
   452 +    if OVERRIDE in command:
   453 +        sys.exit(0)
   454 +
   455 +    cwd = data.get("cwd") or None
   456 +
   457 +    for segment in _SPLIT.split(_strip_prose(command)):
   458 +        parsed = _git_invocation(_tokens(segment.strip()))
   459 +        if not parsed:
   460 +            continue
   461 +        repo_dir, rest = parsed
   462 +        if not rest:
   463 +            continue
   464 +        repo = repo_dir or cwd
   465 +        sub, args = rest[0], rest[1:]
   466 +
   467 +        try:
   468 +            if sub == "push":
   469 +                verdict = _check_push(repo, args)
   470 +            elif sub == "reset":
   471 +                verdict = _check_reset(repo, args)
   472 +            else:
   473 +                continue
   474 +        except Exception:
   475 +            continue  # a guard that crashes must not take the session with it
   476 +
   477 +        if verdict:
   478 +            sys.stderr.write(verdict.message)
   479 +            sys.exit(2)
   480 +
   481 +    sys.exit(0)

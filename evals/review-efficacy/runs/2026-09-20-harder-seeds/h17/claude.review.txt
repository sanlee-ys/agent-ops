- auto-fix: `_guard_is_wired` (line 192) iterates `entry.get("hooks") or []` without checking the type. If `hooks` is a truthy non-iterable such as `true` or `5`, the loop raises `TypeError` outside the parse `try`. The hook then exits non-zero with a traceback instead of the documented loud fail-open, which contradicts the "junk in the `hooks` tree is allowed" claim. Guard with `isinstance(..., list)`, as the code already does for `entries`.
- ask-user: `FORBIDDEN_ENV_KEYS` blocks `ANTHROPIC_BASE_URL`, `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and the AWS keys unconditionally. A gateway or proxy user, or someone who sets an API key in `env` on purpose, will hit a block on a legitimate edit. The PR says a wrong block cannot be repaired, and the repair edit would be blocked too. Should these be blocked outright, or only when the value looks unexpected?

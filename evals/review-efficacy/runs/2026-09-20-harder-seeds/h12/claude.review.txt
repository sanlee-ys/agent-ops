Review of `hooks/destructive-command-guard.py` only. The diff contains this one file. The redaction guard, ADR-015 and the 57 tests named in the PR body are not in the diff, so I could not check them.

- auto-fix: `_DANGEROUS_EXACT` (line 220) lacks a bare `~`, so `rm -rf ~` classifies as `rm.recursive` (0,1). That scores risk 3, which is `warn`, so the guard allows deleting the home directory. Add `~` (and likely `$HOME/`, `/*`-style variants) to the dangerous set so it hits `rm.dangerous_path` and blocks.
- auto-fix: `_classify_rm` (line 256) matches only `-recurse*` for `Remove-Item`. PowerShell also accepts the abbreviation `-r`, so `Remove-Item -r -Force C:\` is not classified and is allowed. Accept any `-r*` prefix that abbreviates `-Recurse`.
- ask-user: `if OVERRIDE in command` (line 402) is a substring test, but the docstring says the token is a prefix. `git commit -m "RISK-OK"; git reset --hard` or `rm -rf / # RISK-OK` bypasses every check. Should the guard require `RISK-OK` at the start of the command or segment, as the docstring says?
- ask-user: `classify` only inspects a segment's first token, so `sudo rm -rf /`, `xargs rm -rf`, `env git reset --hard`, `bash -c "rm -rf /"` and `$(...)` subshells are not scored. This is a bypass on reachable input. Should the guard unwrap common wrappers, or is this an accepted limit to state in the ADR?
- ask-user: the `warn` bucket emits `permissionDecision: "allow"` (line 356). In Claude Code a hook `allow` can skip the normal permission prompt. A warn-scored command (`git branch -D`, `git commit --no-verify`) that the user's `ask` rules would have prompted may now run silently. Should `warn` emit no decision, with context only, so the existing prompt path still applies?
- ask-user: `_load_config` only checks that the config root is an object. `decide` then calls `.get` on `config["rules"]`, `["cells"]` and `["actions"]`. If any of them is not an object (for example `{"rules": []}`), the hook raises `AttributeError` and exits 1. That contradicts the claim that a bad config cannot wedge the shell. The hook also crashes on `tool_input: null` or a non-object stdin payload. It fails open on a non-2 exit, but the documented "ignored with a note" behaviour does not hold.
- Scope fidelity: the code matches the PR description for the scoring, buckets, override, shadow mode, fail-open and exit-2 backstop. I cannot judge the redaction guard, the ADR, the config file or the tests from this diff.

**Summary:** One real bug in the `_SRC_FLAGS` branch of `_copy_operands`, which the new test suite does not cover.

- **auto-fix:** In `security/credential-guard.py` line 1561, the new `_SRC_FLAGS` `=`-attached case takes `tok.split("=", 1)[0]` (the flag name) instead of `[1]` (the value) — the dest-flag branch just above it (line 1552) correctly uses `[1]`. For an `=`-attached src flag (e.g. `rsync --files-from=/home/user/.env dest`), this appends the flag name itself to `positional` instead of the credential source path, so the actual source is never captured or judged. This is the same failure mode ("credential source not judged") that this PR claims to fix, reintroduced in the sibling branch.
- **auto-fix:** `tests/test_credential_guard.py` adds cases only for `_DEST_FLAGS` with `=` (`--target-directory=`). No test exercises `_SRC_FLAGS` with an `=`-attached value, so the bug above ships with no failing test. Add a blocked-case test for an `=`-attached src flag (mirroring the dest-flag cases added at lines 1414–1415) to cover this path.
